    Follow one message.

    Work through the same network under three conditions. Every address stays consistent so you can focus on what changes.

    01

    Learn the normal path

    A needs the MAC for B’s local IPv4 address. Send the broadcast request, then B’s reply. Compare what A and B learn. [1]

    02

    Find the changed entry

    Model two false replies. Check which MAC replaces the correct peer mapping. Predict the next frame’s destination, then send a message. [2], [3]

    03

    Separate the defenses

    Try DAI before the false replies. Then compare TLS, and turn relay off. Observe the difference between blocking a claim, protecting data and losing delivery. [2], [4]

    How to use it

    Start at Normal exchange. Use Send ARP request and Show B’s reply, then send your message. Open False mapping and model the false replies. Read both cache entries and send the same message again. In Compare defenses, enable DAI before modeling a claim, or compare the same poisoned path with TLS enabled.

    Use Clear caches to return both mapping tables to empty while keeping your selected conditions. Rerun ARP to restore the correct entries. Reset all returns the model to its original state. Save record downloads a plain text copy of your current evidence. The quiz scores five first answers and offers a fresh attempt after completion.

    The tool works in a modern browser without installations or logins when opened as an offline file. The hosted copy currently uses private access. No account data is stored by the application. External reference pages need internet access.

    Model assumptions and limits

    These authored examples use one IPv4 subnet and one switched VLAN. Both hosts accept false updates unless DAI rejects them. Real host behavior varies. The switch is present in every path. A data trace shows a logical path, not additional cables.

    The relay scenario assumes M knows the legitimate mappings and forwards without NAT. IP endpoints stay A and B while Ethernet addresses change by leg. TTL, checksums, re-poisoning intervals and platform-specific behavior are outside the model. The TLS view assumes correct peer authentication and validation. It conceals the message from M but does not prevent traffic drops. No real attack, packet capture or automatic attack workflow runs here.

    DAI assumes approved bindings, enabled VLAN inspection and untrusted endpoint ports. Trusted ports bypass inspection on the documented platform. Enabling DAI after poisoning does not restore the cache. Static ARP entries are another option for selected peers, but need accurate upkeep. Mapping-change monitoring can support investigation without blocking a claim. A changed mapping alone does not prove an attack. [2], [3]
